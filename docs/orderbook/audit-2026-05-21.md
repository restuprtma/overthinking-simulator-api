# Orderbook Engine — Audit Findings (2026-05-21)

Audit terhadap `internal/modules/stock/orderbook_consumer/` (book/engine.go, parser, service, snapshotter, sink). Tujuan: identifikasi bug spesifik sebelum membangun WS protocol di atasnya.

## Ringkasan eksekutif

Engine **strukturnya benar** (event-sourced state machine, mutex-guarded, debounced snapshot) tapi ada **3 bug korektifitas** + **3 gap fitur** yang harus diperbaiki sebelum bisa dipakai sebagai sumber data realtime. Tidak perlu rewrite — fix-in-place cukup.

Tidak ada consumer eksternal `orderbook:*` Redis keys saat ini (sudah dikonfirmasi via grep), jadi **breaking changes ke key layout aman**.

---

## Bug list

### B1 — Volume vs Balance semantics 🟥 high
**File:** [book/engine.go:98](internal/modules/stock/orderbook_consumer/book/engine.go#L98), [parser/order.go:139](internal/modules/stock/orderbook_consumer/parser/order.go#L139)

Engine memakai `o.Volume` (original quantity) sebagai remaining lot saat add. Tapi data live menunjukkan vendor kirim Volume ≠ Balance pada record Type 16 (e.g. BBCA: `Volume=10600, Balance=6500` untuk record cmd 1).

Konsekuensi: state engine overcount per order (10600 - 6500 = 4100 shares per BBCA order). Akan self-correct via Type 15 fill events HANYA jika fill events sebelumnya juga ter-konsumsi — kalau consumer attach mid-day, balance discrepancy permanen.

**Fix**: gunakan `o.Balance` untuk `Remaining` saat add (lebih akurat — vendor sudah net-out). Type 15 tetap decrement balance.

### B2 — Duplicate order_no inflates OrderCount 🟧 medium
**File:** [book/engine.go:213-224](internal/modules/stock/orderbook_consumer/book/engine.go#L213-L224)

Path "if duplicate order_no, reverse first" memanggil `removeLevel` (mengurangi Lot, drop level if Lot ≤ 0) tapi TIDAK memanggil `decOrderCount`. Lalu `addLevel` increment OrderCount. Net: jika level masih bertahan (lot tidak sampai 0), OrderCount inflated +1.

**Fix**: panggil `decOrderCount` sebelum `delete(e.orders, ...)` di path duplikat.

### B3 — No session reset, state leaks across days 🟧 medium
**File:** [main.orderbook_consumer.go:23-26](internal/modules/stock/orderbook_consumer/main.orderbook_consumer.go#L23-L26)

Comment akui keterbatasan. OrderNo reset per hari di IDX (per PDF spec) → hari ke-2 collide dengan hari ke-1 → path B1 (duplicate) trigger → OrderCount bug per stock.

**Fix**: 
- Subscribe ke subject `idx.status.>` (Type 57 Trading Status), trigger `engine.Reset()` saat menerima status "1" (Begin sending records) atau "3" (Begin first session).
- Alternatif: cron stop-start consumer 08:50 WIB harian.

### B4 — Investor field "-" disebarkan sebagai domestik 🟨 low (data quirk)
**File:** [parser/order.go:102](internal/modules/stock/orderbook_consumer/parser/order.go#L102)

Live BBCA showed `investor='-'` (100% rows). `IsForeign()` mengembalikan `false` untuk "-" → LotForeign + OrderForeign tetap 0.

Belum jelas apakah:
- Vendor sedang mask investor type untuk live RG board (sama kebijakan dengan broker `--`)
- Live feed broken & tidak kirim F/D
- Specific stock policy

**Fix**: tambah field tracking `investor_unknown` (count "-"), sehingga FE bisa decide whether to render foreign breakdown. Jangan claim 0% foreign jika unknown.

### B5 — Tidak ada per-stock sequence counter 🟥 high (blocking untuk WS protocol)
**File:** [sink/redis.go:138](internal/modules/stock/orderbook_consumer/sink/redis.go#L138)

Existing `_bid_seq` & `_ask_seq` hanyalah unix timestamp string — same value within 1 second, useless untuk gap detection di FE.

**Fix**: tambah `seq atomic.Uint64` per stock di engine; increment per perubahan. Snapshot serialize `seq`, delta carry `seq + prev_seq`.

### B6 — Tidak ada delta tracking / NATS publish 🟥 high (blocking untuk WS realtime)
**File:** [snapshotter/snapshotter.go](internal/modules/stock/orderbook_consumer/snapshotter/snapshotter.go), [sink/redis.go:103](internal/modules/stock/orderbook_consumer/sink/redis.go#L103)

Snapshotter hanya write ke Redis (full per-side overwrite via DEL + HSET). Tidak ada publish event ke NATS. ws-gateway tidak punya sumber update realtime selain polling Redis (latensi tinggi, beban tinggi).

**Fix**:
- Engine track perubahan per-cycle: levels yang baru/berubah/hilang.
- Snapshotter compute delta lalu publish:
  - `idx.orderbook.snapshot.<stock>` — periodic full snapshot (e.g. 5 detik atau on-demand)
  - `idx.orderbook.delta.<stock>` — incremental, per 100ms throttle cycle
- Tetap simpan ke Redis db 9 sebagai source-of-truth untuk cold-start FE.

## Decisions (akan diterapkan)

| # | Decision | Reason |
|---|---|---|
| D1 | Use `o.Balance` for `Remaining` saat add | Lebih akurat untuk bootstrap, tidak menggantungkan urutan event 15 vs 16 |
| D2 | Store **shares** in LevelStats, expose **lot** di output JSON | Conversion divide-by-100 di sink/snapshot serializer; lot adalah unit IDX standard untuk display |
| D3 | Session reset via subject `idx.status.*` (Type 57); fallback midnight cron | Avoid manual restart |
| D4 | Per-stock monotonic seq `int64` mulai dari 1 per reset | Standar pola Binance/Bybit |
| D5 | NATS subject layout: `idx.orderbook.delta.<stock>` + `idx.orderbook.snapshot.<stock>` | Konsisten dengan `idx.candle.<stock>.<tf>` |
| D6 | Redis db 9, key layout (revised) — lihat protocol.md | Single source for cold-start; ws-gateway baca dari sini saat subscribe |
| D7 | Field naming JSON: `p, l, f, lf, ff, ts, seq` (singkat) | Hemat bandwidth, ribuan delta/menit per stock |
| D8 | Depth default 10, server-capped 30 | Cukup untuk display; protect bandwidth |

## Eksklusi (tidak diperbaiki di iterasi ini)

- **Type 18 Best Quote consumer**: Tidak diaktifkan. Engine pakai Type 16 + 15 sebagai source. Type 18 ke depan bisa dipakai sebagai ground-truth untuk validation (compare engine state vs vendor aggregate).
- **Broker breakdown per level**: Live broker code = `--`. Tidak ada nilai informasi sampai Type 26 resend post-close. Tidak masuk display realtime.
- **Order amend** (modify price/qty): IDX tidak punya event modify — modify = cancel + new order. Tidak perlu handling khusus.
- **Pre-opening / post-trading phase tagging**: Bisa dilakukan via subject `idx.status.>` listener; bukan blocker FE.

## Risiko

| Risiko | Mitigasi |
|---|---|
| Engine restart mid-day → tetap kehilangan orders sebelum attach | DELIVER policy already `AllPolicy` — jika stream punya retention sejak market open, replay dari awal. Tapi practical: state akan benar dalam ~5 menit setelah restart karena order Type 16 dengan cmd=0/1 + balance memperbarui posisi |
| `investor='-'` untuk semua live records | Belum jelas penyebab. Foreign breakdown bakal 0 di display. Treat as "data missing", bukan "no foreign activity". Confirm dengan tim publisher / IQPlus support |
| Snapshot+delta race saat client subscribe | Snapshot dari Redis = state at moment T. Delta yang arrive setelahnya carry seq. Bila delta seq ≤ snapshot seq → diskard. FE wajib track local seq. |
| Beban NATS dari publish per-stock delta | Throttle di server 100ms (sudah ada). Delta hanya untuk stock yang ada perubahan (sudah ada di DrainDirty). |
